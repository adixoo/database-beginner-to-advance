A table is saved to disk in four steps. PostgreSQL, MySQL and SQLite all work this way. We will follow this table:

```sql
CREATE TABLE notes (id INTEGER PRIMARY KEY, body TEXT);

INSERT INTO notes (id, body) VALUES (1, 'Buy milk'), (2, 'Call Ravi'), (3, 'Book the trek');
```

### 1. Split the table

<TableBreakdown />

The column names and types, the **schema**, are saved once ([How the schema is stored](/advanced/how-the-schema-is-stored)). Each row is saved as a **tuple**: just its values, in column order.

### 2. Turn each tuple into bytes

<RowToBytes />

A small **header** comes first, then the values, one after another.

#### What the header holds

The header is a few bytes at the start of every row that describe the values after it:

<RowHeader />

- **Sizes:** values can be different lengths, so the row notes how many bytes each one takes. Without that, the database could not tell where `'Buy milk'` ends.
- **NULLs:** a `NULL` takes no space among the values. The header just marks it as missing.

Each engine's header is a little different:

| Engine         | What the row starts with                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| PostgreSQL     | About 24 bytes: a NULL flag for each column, and which transaction wrote the row. Each text value carries its own length just before it. |
| MySQL (InnoDB) | The lengths of the variable-size values, a NULL flag for each column, and hidden columns saying which transaction wrote the row          |
| SQLite         | One small code per column, giving its type and size                                                                                      |

### 3. Pack rows into a page

The row's bytes go into a **page**: a fixed-size box that holds many rows. Each row gets a numbered **slot**, so it can be found again later.

<PageWithRows />

When the free space runs out, the page is full, and the next row goes into a new page. Every page in a database is the same size:

| Engine         | Page size |
| -------------- | --------: |
| PostgreSQL     |      8 KB |
| MySQL (InnoDB) |     16 KB |
| SQLite         |      4 KB |

### 4. Save the pages as a file

<TableAsPages />

The table's file is just its pages, one after another.

## Words to know

<WordsToKnow>

- **Page**
  A fixed-size block of a database file, such as 4, 8 or 16 KB, holding many rows.
- **Schema**
  A table's column names and types, saved once.
- **Slot**
  An entry in a page that says where one row sits inside it.
- **Tuple**
  One row's values in column order, without the column names.

</WordsToKnow>
