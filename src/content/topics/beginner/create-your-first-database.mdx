Let's build a tiny Instagram: a database with a table for users and a table for their posts. We will use **SQLite**, because the whole database is a single file and there is no server to set up.

## Plan your schema

The **schema** is the plan for your tables. Each kind of thing becomes a table, and each detail about it becomes a column:

| Table | Column   | Type    | Rule                       |
| ----- | -------- | ------- | -------------------------- |
| users | id       | INTEGER | Primary key                |
| users | username | TEXT    | Required, no duplicates    |
| users | name     | TEXT    | Required                   |
| posts | id       | INTEGER | Primary key                |
| posts | user_id  | INTEGER | Required, points to a user |
| posts | caption  | TEXT    | Optional                   |

`INTEGER` holds whole numbers like `42`, and `TEXT` holds words like `'asha.codes'`; [Data types](/beginner/data-types) covers the rest. Every table gets an `id`, so each row has a number that never repeats.

To see your tables drawn as a diagram, use the [Sequill schema designer](https://sequill.adibitz.com/vis), or pen and paper.

## Create the database

You can follow along with any [DBMS](/beginner/what-is-a-database#what-is-a-dbms) and editor you like. In this course we use [Sequill](https://sequill.adibitz.com/app), a free SQLite editor made specially for this course: it runs in your browser, so there is nothing to install.

Use this one database for the whole course: every example builds on the ones before, so run them in order.

Prefer the terminal? [Download SQLite](https://www.sqlite.org/download.html), then run:

```bash
sqlite3 instagram.db
```

## Create the tables

`CREATE TABLE` takes the table name, then each column with its type and rules:

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  username TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL
);

CREATE TABLE posts (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users (id),
  caption TEXT
);
```

- `PRIMARY KEY` gives each row its own number, filled in for you.
- `NOT NULL` means the column is required.
- `UNIQUE` stops two users from having the same username.
- `REFERENCES users (id)` makes `user_id` a **foreign key**: every post points to a user.

That's it: your database has two tables and is ready for data. Next, [add and read rows](/beginner/working-with-a-database).

## Words to know

<WordsToKnow>

- **Constraint**
  A rule a column must follow, such as NOT NULL or UNIQUE.
- **Data type**
  The kind of value a column holds, such as INTEGER or TEXT.
- **Foreign key**
  A column that points to a row in another table.
- **Primary key**
  The column whose value is unique for every row.
- **Schema**
  The plan for your tables: columns, types and rules.

</WordsToKnow>
